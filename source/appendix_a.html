附录 B　六个核心一页速查

核心一句话对热点问什么
看见认识从划一道线开始，而划线有成本在划什么线？谁被排除？
记住遗忘不是失败，是有限容量的账单被压成什么标签？丢了什么？
跟上不是不知道，是来不及快钟 vs 慢钟；τ 多大？
选择完备、可组合、传递，紧预算下至多取二各方要哪两样？让出哪一样？
讲述诠释就是给竞争命题分配置信度在哪一层？抢位置还是争事实？
临界量变到质变：序参量跃变、临界慢化、有效信息峰值跨过临界点了吗？三中几？

证据等级：A 官方可复现 / B 稳定公开估计 / C 稀疏·构造·思辨。 概念等级：甲 成熟形式化 / 乙 有论证但依赖未证前提 / 丙 思辨假说。 合并写作：A／甲。纪律：结论强度不超过证据强度。

附录 C　数据采集脚本与来源

本书配套脚本（均为低频、带缓存、失败即停，不绕过平台风控）：

  • analysis/collect_zhihu.py —— 抓取知乎热榜/关键词（公开接口；搜索需登录态 Cookie）。
  • analysis/collect_x.py —— 调用 X API v2（需 Bearer Token；recent search 仅覆盖最近 7 天，完整历史需更高访问等级）。
  • analysis/cluster_events.py —— 去重、聚类、按热度和时间排序，输出 data/events.json。

数据来源与口径：知乎、X 的公开内容与公开指标。第三方内容的权利归原作者与平台所有；本书只作结构性诊断，不用于对个人的评价。

怎样新增一个事件： 1. 运行采集脚本（或在 data/events.json 手工添加一条）； 2. 按附录 可证伪登记簿 的模板填写诊断卡； 3. 在 data/events.json 里为它补上 evidence（A/B/C）与 refutable（可反驳条件）； 4. 重新构建，即生成新的案例章节。

附录 G　合并词典（同义合并示例）

合并规则写在这里，便于你反对它。右列是判断依据。

合并为子条目（实际榜单写法）并入理由
低成本爱好你的低成本爱好是什么 / 你有什么解压的小众爱好同一类问题，且时间上不重叠
自我提升提升自己最快的方式（三种写法）/ 人在什么情况下成长最快同一主题的语序变体
黄金拐点黄金什么时候会大跌 / 黄金什么时候会暴跌 / 黄金到底能涨到什么地步同一焦虑的三种表述
中东危局速览中东危局40小时 / 以色列宣布袭击伊朗 / 伊朗局势 / 美以袭击伊朗 / 伊朗会不会成为下一个伊拉克同一事件簇，保留子条目
彩礼 / 婚恋（保留分开）不合并：一个是制度，一个是关系
A 股 / 美股（保留分开）不合并：不同市场、不同受众

原则： 只合并“同一事、同一焦虑、不同问法”；不合并“同一字、不同对象”。每一条合并都会改变排名，所以必须公开。

附录 J　常见问题八条

问简答
我不懂统计，能用吗？能。六把尺子里只有“跟上”需要一个比值，其余都是提问。
它能告诉我股票涨跌吗？不能。它只能告诉你这场讨论卡在哪一层。
为什么没有结论？因为诊断的结论是“账单在哪里”，不是“你该怎么做”。
为什么案例都很短？因为诊断靠结构，不靠篇幅；长卡在第十四章。
我能把它用在家庭吗？能，而且最有用。但要先说好“不评价人，只算账”。
数据在哪？仓库 data/；脚本在 analysis/。
发现错误怎么办？开 issue。能公开改错的书，才值得被引用。
下一步读什么？通俗读本《只能选两样》，或直接读本系列专著。
