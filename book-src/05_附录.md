## 附录 B　五个核心一页速查

| 核心 | 一句话 | 对热点问什么 |
|---|---|---|
| 看见 | 认识从划一道线开始，而划线有成本 | 在划什么线？谁被排除？ |
| 记住 | 遗忘不是失败，是有限容量的账单 | 被压成什么标签？丢了什么？ |
| 跟上 | 不是不知道，是来不及 | 快钟 vs 慢钟；τ 多大？ |
| 选择 | 完备、可组合、传递，至多取二 | 各方要哪两样？让出哪一样？ |
| 讲述 | 诠释就是给竞争命题分配置信度 | 在哪一层？抢位置还是争事实？ |

**证据等级**：A 官方可复现 / B 稳定公开估计 / C 稀疏·构造·思辨。
**概念等级**：甲 成熟形式化 / 乙 有论证但依赖未证前提 / 丙 思辨假说。
**合并写作**：`A／甲`。**纪律：结论强度不超过证据强度。**

## 附录 C　数据采集脚本与来源

本书配套脚本（均为低频、带缓存、失败即停，不绕过平台风控）：

- `analysis/collect_zhihu.py` —— 抓取知乎热榜/关键词（公开接口；搜索需登录态 Cookie）。
- `analysis/collect_x.py` —— 调用 X API v2（需 Bearer Token；`recent search` 仅覆盖最近 7 天，完整历史需更高访问等级）。
- `analysis/cluster_events.py` —— 去重、聚类、按热度和时间排序，输出 `data/events.json`。

**数据来源与口径**：知乎、X 的公开内容与公开指标。第三方内容的权利归原作者与平台所有；本书只作结构性诊断，不用于对个人的评价。

**怎样新增一个事件**：
1. 运行采集脚本（或在 `data/events.json` 手工添加一条）；
2. 按附录 A 的模板填写诊断卡；
3. 在 `data/events.json` 里为它补上 `evidence`（A/B/C）与 `refutable`（可反驳条件）；
4. 重新构建，即生成新的案例章节。
